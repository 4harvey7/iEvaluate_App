SUBJECT MANAGEMENT - BULK IMPORT AND MANUAL ADD [LIVE DATA]

Preconditions

Drawer item "Subject Management" is reachable. The n8n bulk import workflow is running. A Google Sheet of subject assignments is prepared for the active term.

Test Data

One prepared sheet, plus one manual subject. Webhook URL comes from the env var for subject bulk import.

Steps
1. Open the drawer and tap "Subject Management".
Expected: The screen lists subject assignments for the active term and states which term that is.
2. Use the search box and the assigned/unassigned filter.
Expected: Search narrows the list, and the filter separates subjects that have an instructor from those that do not.
3. Add ONE subject manually with valid details.
Expected: It is created and appears in the list against the active term.
4. Add a NEW subject reusing the code from step 3, with a DIFFERENT name.
Expected: Refused. A dialog headed "Subject Code Already Used" names the subject holding that code and its department. Reopen the original subject afterwards and confirm its name was NOT rewritten - silently overwriting it is the defect this step exists to catch.
5. Add a NEW subject with a different code but the SAME name as step 3.
Expected: A dialog headed "Possible Duplicate" names the existing code. "Cancel" creates nothing. Repeat and choose "Create anyway" and it is created - one name under two codes is allowed, but only deliberately.
6. Open a subject, tap Remove beside an instructor whose assignment has NO evaluation records.
Expected: A progress indicator appears while it checks, then a confirm dialog, then the instructor is removed and the list refreshes.
7. Repeat step 6 on an assignment that HAS evaluation records - management results, performance results or student remarks, any ONE of the three is enough.
Expected: A dialog headed "Cannot Remove" states how many records exist. The delete is never attempted and the instructor is still listed afterwards. A case with only performance results or only remarks matters most here: those used to read as zero, so the app promised the removal was safe and the database then refused it.
8. Open the edit sheet for an existing assignment, clear the instructor field and save.
Expected: Refused, with a message pointing at the Remove button. The sheet must NOT close reporting success while leaving the instructor still assigned.
9. Run "Import from Google Sheets" with the prepared sheet.
Expected: The import runs via the n8n webhook, reports progress, and ends with a clear success or failure message - never an indefinite spinner.
10. Cross-check the imported rows against the sheet.
Expected: Every row in the sheet is either imported or reported as an error. Nothing is silently dropped.
11. Deliberately include a bad row (unknown instructor, unknown subject) and re-import.
Expected: The bad row does NOT import silently. It is recorded as an import error and triaged in the SAO Staff module (UAT_SAO_Staff TC-S08), not here.
12. Run the import with n8n stopped.
Expected: A clear failure message. No partial import is left behind.
13. Attempt to delete a subject that already has evaluation results.
Expected: Deletion is BLOCKED. Results already recorded against a subject cannot be orphaned.
Expected Result

Subjects can be added manually and in bulk, a subject code can never be given to a second subject, bad rows are reported rather than silently dropped, an instructor can be unassigned only while no evaluation records exist, and a subject carrying results cannot be deleted.
