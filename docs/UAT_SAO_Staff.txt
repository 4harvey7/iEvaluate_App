WHAT THIS ROLE DOES
  The SAO Staff member is the person who physically scans completed paper SAST
  evaluation forms into the system. Their work is a pipeline:

      scan a form  ->  it queues locally  ->  it uploads to n8n  ->
      anything n8n cannot read is flagged  ->  staff corrects it  ->  it syncs

  This document tests that pipeline, because that is where the role's real work
  and its real risk of data loss sit. Everything else is secondary.


--------------------------------------------------------------------------------
HOW TO READ THIS DOCUMENT
--------------------------------------------------------------------------------
* Text in "double quotes" appears on screen exactly as written.
* Names in [square brackets] are database tables, edge functions or n8n
  webhooks to check when a step needs back-end verification.
* Each step has its own expected result.
* "Actual Result" is blank where the case has not been run on this build.
* "Revision" says how the case changed for the 2026-10-28 build.
* "Account Needed" names the role of the account the tester signs in with.
* [DESTRUCTIVE] marks a case that changes or removes shared data (discards,
  deletes, term change). Run it only on records made for testing, and agree
  it with the team first.
* All n8n calls now go through the Supabase [n8n-proxy] edge function.

!! DATA-LOSS WARNING !!
  A scanned form represents a real student's evaluation that exists on paper
  only once. Cases marked [LIVE DATA] upload or discard real records. The
  single most important property in this whole module is that A SCAN IS NEVER
  SILENTLY LOST. Several cases below exist only to prove that.
